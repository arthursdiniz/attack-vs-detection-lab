# Microsoft Sysmon Configuration Engineering Guide

## 1. Overview & Detection Strategy

In an enterprise endpoint, logging every single operating system event creates extreme log volume (noise), saturates SIEM ingestion buffers, and leads to analyst alert fatigue. Conversely, overly restrictive filtering creates fatal blind spots.

Our custom [sysmonconfig.xml](sysmonconfig.xml) is engineered specifically for the **Attack vs Detection Lab**. Rather than importing a generic 2,000-line community template, it follows a purposeful detection-engineering philosophy:
1. Monitor adversary behaviors (LOLBins, staging directories, persistence keys, lateral movement ports).
2. Suppress high-volume, predictable Windows background system operations.
3. Explicitly filter out telemetry generated by our own monitoring agents to prevent recursive logging loops.

## 2. Telemetry Ingestion Breakdown

### 2.1 Event ID 1: Process Creation

#### What We Monitor:
- **Living-off-the-Land Binaries (LOLBins) & Interpreters**: `powershell.exe`, `pwsh.exe`, `cmd.exe`, `wscript.exe`, `cscript.exe`, `rundll32.exe`, `regsvr32.exe`, `certutil.exe`, `wmic.exe`.
- **Account & Group Management Binaries**: `net.exe`, `net1.exe`.
- **System & Network Discovery Utilities**: `whoami.exe`, `nltest.exe`, `systeminfo.exe`, `tasklist.exe`, `ipconfig.exe`, `netstat.exe`, `route.exe`, `arp.exe`.
- **Suspicious Execution Directories**: Any execution initiating from or located within:
  - `\AppData\Local\Temp\`
  - `\Users\Public\`
  - `C:\Windows\Temp\`
- **Hashing**: MD5 and SHA256 hashes generated for every executed binary image.

#### Why We Monitor It:
Adversaries frequently leverage built-in Windows administrative utilities to blend in with legitimate system activity (Defense Evasion - T1036 / Living off the Land). Capturing the full `CommandLine`, `ParentImage`, and `ParentCommandLine` provides the exact context needed to distinguish an interactive admin from an automated script or injected payload.

#### What Is Excluded & Noise Reduction:
- `audiodg.exe`, `SearchFilterHost.exe`, `SearchProtocolHost.exe`: High-frequency internal Windows daemons that spawn continuously without user interaction.
- `conhost.exe`: Excluded when spawning benign console hosts.
- **Agent Loop Prevention**: Any process where `ParentImage` is `C:\Program Files (x86)\ossec-agent\wazuh-agent.exe`. This prevents Wazuh's own active-response and command checks from creating recursive alert loops.

### 2.2 Event ID 3: Network Connection

#### What We Monitor:
- Network connections initiated by scripting engines and interpreters: `powershell.exe`, `cmd.exe`, `rundll32.exe`, `certutil.exe`, `curl.exe`.
- Any process attempting outbound or inbound connections on sensitive administrative and lateral movement ports:
  - Port `22` (SSH)
  - Port `445` (SMB)
  - Port `3389` (RDP)
  - Port `5985` (WinRM)
  - Port `8080` (Alternative Web / Test API)

#### Why We Monitor It:
Scripting tools like PowerShell or `certutil` have no legitimate business establishing direct outbound connections in a healthy baseline unless actively used for software delivery or remote management. Detecting socket creations from these binaries exposes C2 callbacks, staged payload downloads (T1105), and lateral port scans.

#### What Is Excluded:
- Local loopback connections (`127.0.0.1`, `::1`).
- The Wazuh Agent itself connecting to `192.168.56.40:1514`. If this were not excluded, every transmitted alert would trigger a new network connection event, resulting in an exponential log storm.

---

### 2.3 Event ID 11: File Creation

#### What We Monitor:
- Dropping or creation of executable files and scripts: `.exe`, `.ps1`, `.bat`, `.vbs`, `.dll`.
- Any file creation occurring in non-standard, user-writable staging locations:
  - `C:\Users\Public\`
  - `C:\Windows\Temp\`
  - `\AppData\Local\Temp\`

#### Why We Monitor It:
Malware droppers, exploit frameworks, and adversaries commonly stage tools and temporary scripts in world-writable folders before execution. Detecting the creation event provides an early warning indicator and captures file hashes prior to execution.

#### What Is Excluded:
- Temporary installer noise (`.tmp`, `.log`).
- File creation driven directly by official Windows Installer routines (`msiexec.exe`).

---

### 2.4 Event ID 12 / 13 / 14: Registry Modifications

#### What We Monitor:
- Common persistence auto-run locations:
  - `HKLM\Software\Microsoft\Windows\CurrentVersion\Run`
  - `HKLM\Software\Microsoft\Windows\CurrentVersion\RunOnce`
  - `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
- Service creation and configuration tampering:
  - `HKLM\System\CurrentControlSet\Services`
- Security control tampering:
  - Modifications to `Windows Defender` and `Windows Firewall` policy keys.

#### Why We Monitor It:
Adversaries establish persistence across reboots by registering binary paths in registry autostart keys (T1547.001) or disable defensive protections (T1562.001) via registry manipulation.

#### What Is Excluded:
- Transient background service usage telemetry like `\Services\bam\UserSettings`.

## 3. How to Deploy & Verify Sysmon

On `lab-win11` in an elevated PowerShell session:

```powershell
# 1. Apply or update the custom configuration
& "C:\Program Files\Sysmon\Sysmon64.exe" -c "C:\LabSetup\sysmonconfig.xml"

# 2. Verify that the configuration was loaded
& "C:\Program Files\Sysmon\Sysmon64.exe" -s

# 3. Inspect recent Sysmon events via PowerShell
Get-WinEvent -LogName "Microsoft-Windows-Sysmon/Operational" -MaxEvents 5 | Format-List TimeCreated, Id, Message
```
